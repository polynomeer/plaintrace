## 기준과 범위

브랜치: `codex/prioritized-code-fixes`. 보존 기준은 커밋 `758bfc5`의 태그 `archive/pre-improvements-2026-10-13`이며 기준 태그와 2017년 합성 커밋 263개는 변경하지 않으며 개선은 일반 병합으로 master에 통합할 수 있습니다. 원본 해시는 source-manifest.json에 유지합니다. 소스 변경은 파일별 인코딩, BOM과 CRLF를 보존하고 실제 현재 날짜로 커밋합니다. 이는 유지보수 개선이며 새로운 과거 히스토리 재구성이 아닙니다.

별도 표기가 없는 수동 작성 사후 문서는 태그의 아카이브를 설명합니다. 자동 생성 [코드 구조](CODE_STRUCTURE.ko.md)와 [스키마 참조](SCHEMA_REFERENCE.ko.md)는 이 브랜치를 설명합니다. 아래 수정 사항은 기존 결함 설명보다 이 기록을 우선 적용합니다.

## 검증

```sh
python3 tools/test_improvements.py
python3 tools/generate_source_reference.py --check
python3 tools/verify_documentation.py
python3 tools/verify_archive.py --archive-only
git diff --check
```

휴대 가능한 회귀 검사 11개는 소스 인코딩/구조, 타임라인 스키마와 IE 삽입 템플릿, 독립 브라우저 쿼리, 행 복사 매핑, USB CSV 특수 문자, Recent SQLite 특수 문자와 종료 시각 증거 읽기 코드를 확인합니다. Python SQLite는 소스에서 추출한 SQL을 실행하며 출력 검사는 선택한 문자열 표현식을 평가하고 명시된 인용 처리를 모델링합니다. EnScript를 컴파일하거나 실행하지 않으므로 API 호환성을 입증하지 않습니다. Windows/EnCase 컴파일과 T-02/T-08/T-09/T-10/T-11/T-12 실행이 필요합니다. 특히 실제 호스트에서 새 리더 수명, FILETIME 해석과 출력 실패 정리를 확인해야 합니다.

아카이브 전용 검증은 과거 Git blob을 읽어 기록 263개를 확인하고 과거 트리와 원본 로컬 백업 ref를 비교합니다. 기본 아카이브 검증은 변경된 작업 소스를 계속 거부하므로 이 브랜치를 아카이브와 바이트가 같다고 표현해서는 안 됩니다. 일반 clone에서 원본 트리까지 대조하려면 별도 보존한 로컬 백업 ref가 필요합니다. 휴대 가능한 개선 검사에는 보존 기준 태그가 필요합니다.

## 남은 작업

고정 오프셋 Prefetch/$I 형식 지원(R-01), 시간대 해석(R-02), 수정한 핸들러 외 SQL 인용 및 출력 왕복(R-03), 차트/재실행 동작과 파일 경합(R-05), 전체 워커 정리(R-07), 누락된 HTML/JS와 고정 브라우저 실행 경로(R-08), 출처 필드/스키마 마이그레이션(R-09)은 남아 있습니다. 추가 형식 지원이나 시간 해석 변경에는 기대 값이 독립적으로 알려진 픽스처와 호스트 검증이 필요합니다. 합성 증거 결과나 과거 테스트 통과를 주장하지 않습니다.

일반적인 URL/제목 값으로 검사한 범위 외의 브라우저 삽입 템플릿은 여전히 인용 처리가 없는 문자열 연결을 사용합니다. 스키마와 VALUES 수정이 모든 브라우저 작성 경로의 작은따옴표 문제를 해결했다고 해석하면 안 됩니다. 휴지통 추출도 메타데이터와 복구 내용을 구분하는 검증이 필요합니다.
