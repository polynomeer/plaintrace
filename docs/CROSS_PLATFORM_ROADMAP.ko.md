## 작업 패키지·의존 관계

기간은 숙련 유지보수자 1명의 인주 추정이며 실제 증거 접근 지연은 제외하고 일정 확약으로 사용하지 않습니다. 현재 SAM 기준점에서 현대 작업 브랜치를 만들고 역사 브랜치를 재사용·재작성하지 않습니다. 각 구현 PR은 양언어 계약·fixture·테스트 결과·지원 등록부 갱신을 포함합니다.

## 아티팩트별 구현 작업

macOS: 먼저 명시적으로 획득한 SystemVersion 계열 plist 값을 해석하며 소유자를 추정하지 않습니다. XML/binary 타입·날짜·위치 참조를 보존합니다. Safari는 검토한 테이블·컬럼 스키마와 별도 명세한 시간 단위만 허용합니다. native unified log·Spotlight·FSEvents는 지원 선언 없이 별도 조사 티켓으로 둡니다.

Linux: os-release 대입문은 셸 실행·source 없이 해석하고 리터럴 필드·진단을 유지합니다. passwd/group은 계정 메타데이터로 다루며 shadow hash나 유효 권한을 해석하지 않습니다. journal은 획득 export부터 시작하며 호스트 journalctl 호출이나 native .journal 지원을 약속하지 않습니다. 바이너리·중복 필드·cursor·boot/realtime/monotonic 구분을 보존합니다. 텍스트 로그는 명시적 생성 프로그램 프로필이 필요하며 연도·시간대를 추정하지 않습니다.

Windows: 기존 의미상 제외 범위를 유지합니다. XP 시대·현대 클라이언트/서버·신규 포맷 확장 전에 어댑터별 현재 허용 리비전을 목록화합니다. 제한된 레이아웃 파싱과 독립 기대값이 있을 때만 리비전을 추가합니다. 상관분석·카빙·자격 증명 추출은 호환 작업에 포함하지 않습니다.

독립적으로 기대값을 구성한 단위 fixture 이후 속성·변형 검사와 격리 mutation fuzzing을 수행합니다. 호스트 비교에서는 명시적 실행 메타데이터만 제외하며 원시 관측·진단은 비교합니다. 획득 fixture는 적법한 출처·동의/라이선스·비식별 검토를 거쳐 Git 밖에 보관하고 해시로 식별합니다. 독립 도구는 비교 대상이며 무조건적 정답이 아닙니다. 불일치를 기록하고 해결될 때까지 해당 지원 선언만 보류합니다.

## CI·패키징·릴리스 기준

러너 OS 이미지를 고정하고 정확 build·CPU·Python·의존성 버전을 기록합니다. PR 트랙 제안: 3개 주 호스트 계열, 선언 최소 Python, 릴리스에서 선정한 안정 Python, 지원 선언 호스트마다 전체 EVTX integration 실행. 야간·릴리스 트랙에서 추가 interpreter minor·ARM64·libc 변형·구형 증거 fixture를 확장합니다. 호스팅 러너 이름만으로 구형 버전을 인증하지 않습니다. 러너나 의존 wheel이 없으면 해당 조합은 미검증으로 남습니다.

순수 Python wheel부터 배포하고 선택 native 어댑터는 의존성·라이선스 목록을 고정해 별도 패키징합니다. 깨끗한 설치·console 진입점·오프라인 실행·의존성 부재 진단을 검증합니다. 컨테이너 검증은 그 Linux 환경만 해당하며 Windows/macOS 검증을 대신하지 않습니다. 실행 파일 bundle·서명/notarization·installer는 별도 릴리스 작업과 호스트 smoke test가 필요합니다.

릴리스는 필수 테스트 전체 통과, 입력 변경·데이터 손실·경계 오류 미해결 없음, 스키마 이전 검토, 지원 등록부·문서 일치, 아카이브 검사를 요구합니다. 증거 내용 없이 환경·결과·해시를 공개합니다. 회귀 시 해당 패키지·지원 선언을 철회하고 이전 호환 버전을 제공하며 이전 보고서·증거를 덮어쓰지 않습니다.

## 위험·담당·후속 결정

유지보수 담당은 지원 선언·아카이브 보호, 어댑터 구현자는 포맷 판정·원시 의미, 검토자는 독립 기대값, 릴리스 담당은 호스트 근거·패키징에 책임을 집니다. 이는 배정할 역할이며 현재 인력이 배치됐다는 뜻은 아닙니다.

주요 위험은 구형 fixture 부재, macOS 독점 포맷 변화, Linux 생성 도구·설정 다양성, Windows 결과 발행 의미, 디코딩 출력 폭증입니다. 근거 중심 범위 설정·export 우선 어댑터·명시적 미지원 진단·호스트 테스트·공유 예산으로 대응합니다. M5 조사가 지연되면 첫 릴리스를 M0–M4 핵심 포맷으로 좁히고 지원 범위를 꾸며내지 않습니다.

다음 구현 결정은 M0에서 호스트 build·CPU·적법한 fixture 접근·인터프리터 정책을 확정하는 것입니다. native 이미지 파싱·수집 에이전트·GUI는 핵심 호환 근거가 마련된 뒤 별도 범위를 결정합니다. 이번 문서는 자동화 예약·서비스 배포·런타임 코드 변경을 수행하지 않습니다.
