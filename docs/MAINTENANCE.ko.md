## 작업 원칙

AGENTS.md, [분석](ANALYSIS.ko.md), [히스토리](HISTORY.ko.md)를 읽습니다. 도구로 디코딩하며 보존 기준의 UTF-16/UTF-8·BOM·CRLF를 변환하지 않습니다. 수정은 실제 날짜와 동작 변경을 가진 새 커밋으로 남기고 합성 기록을 다시 쓰지 않습니다. 소스를 의도적으로 변경하면 새 기준을 별도 문서화하며 기존 매니페스트 해시를 조용히 바꾸지 않습니다.

파서를 수정할 때 독립 모듈과 TimeLineThreadClass 대응 구현을 함께 찾습니다. 내보내기·행 생성자·사본·스키마 변형·시각을 확인하고 동일 fixture로 두 경로를 검증합니다. 영문·국문 문서를 함께 갱신합니다.

## 데이터 취급 경계

케이스 증거를 읽고 파생 결과를 로컬에 쓰며 북마크는 호스트의 케이스 상태입니다. 사용자·계정·문서 경로·URL·장치 ID가 결과에 포함될 수 있습니다. fixture와 결과는 Git 밖에 두고 실제 케이스 절차에서 접근·보관 결정을 기록합니다. 소스에는 암호화·접근 제어 서비스·변조 탐지 서명·완전한 감사 추적이 구현되어 있지 않습니다. SHA-256 아카이브 검사는 소스 무결성이며 결과 증거의 chain of custody를 입증하지 않습니다.

## 향후 개선 순서 제안

1. 재현 가능한 EnCase 작업 환경과 통제 fixture 구성.
2. 재현한 복사·내보내기·시각·스키마 결함부터 수정하고 무관한 포맷 변경 제외.
3. 포맷 탐지·출력 소유·완료/오류 보고 명시.
4. 모듈·타임라인 회귀 검사 후 공통 파서·결과 인터페이스 도입.
5. 명시적 스키마·시간대 계약으로 시각화 복원 또는 대체.

향후 제안이며 현재 구현 기능이 아닙니다. 일정·예산·담당자를 지정하지 않습니다.

## 변경 검토 체크리스트

소스 커밋·fixture·양쪽 파서 경로·전후 출력 예·스키마 영향·인코딩 보존·런타임 증거·양 언어 문서 변경을 기록합니다. 기존 기준을 유지하는 변경에 적절한 아카이브 검사를 적용합니다. 파서 변경은 해시를 의도적으로 바꾸므로 새 기준을 문서화해야 하며 기존 해시 검사 통과를 주장하면 안 됩니다.
