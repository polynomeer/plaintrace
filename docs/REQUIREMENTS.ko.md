# 요구사항과 유스케이스

[English](REQUIREMENTS.md) | **한국어**

2026-10-13 보존된 소스를 기준으로 작성한 사후 문서입니다. 2017년 당시의 원본 산출물이 아닙니다.

## 작성 기준

소스에 대응시킨 사후 요구사항이며 당시 명세를 복구한 문서가 아닙니다. “구현 확인”은 코드 존재를 뜻하며 인수 테스트 통과를 뜻하지 않습니다.

| ID | 요구사항 | 구현 근거 | 상태 / 제약 |
| --- | --- | --- | --- |
| FR-01 | Windows 케이스의 통합 모듈 화면 제공 | MainClass.Main / MainDialogClass | 구현 확인; 처음 일치하는 볼륨에서 진입 순회 종료 |
| FR-02 | 시스템·계정 데이터 조회 | Win_SystemInfo / Win_UserAccount | 구현 확인; 레지스트리·버전 가정 |
| FR-03 | 파일·삭제 메타데이터 분석 | Win_FileMetaData / Win_RecycleBin | 구현 확인; 고정 $I 구조 |
| FR-04 | 실행 흔적·최근 문서 조회 | Win_PrefetchFile / Win_LinkFile / Win_RecentDocuments | 구현 확인; 고정 오프셋과 대조 제약 |
| FR-05 | 로그인·전원·USB 이력 조회 | Win_PowerLogOnOff / Win_USBInfo | 구현 확인; 지정 이벤트 ID·경로 |
| FR-06 | 브라우저 활동·다운로드 조회 | Win_WebVisitKeyword / Win_WebDownloads | 구현 확인; 과거 DB 구조 |
| FR-07 | 결과 필터·북마크·내보내기 | Handler/메뉴/Dialog 구현 | 구현 확인; 모듈별 동작 차이 |
| FR-08 | 통합 타임라인 DB 생성 | TimeLineThreadClass.Run | 구현 확인; 중복된 별도 파서 |
| FR-09 | 웹 타임라인 표시 | TimeLineDialogClass 브라우저 버튼 | 아카이브 불완전; 외부 자산 누락 |
| NFR-01 | 보존 소스 바이트 유지 | source-manifest.json / verify_archive.py | 재구성 작업 공간에서 검증 |
| NFR-02 | 결과 출처 추적 | 케이스 항목·북마크·경로·내보내기 | 부분적; 통일된 출처·이벤트 모델 없음 |
| NFR-03 | 비정상 입력·반복 실행 처리 | 기존 검사·DB 호출 | 미검증; 검토 필요 |
| NFR-04 | Windows EnCase에서 실행 | 호스트 API 의존성 | 정확한 호스트 버전 미확인 |

## 유스케이스

| ID | 사용자 / 사전 조건 | 기본 흐름 | 완료 / 대안 |
| --- | --- | --- | --- |
| UC-01 | 분석자; Windows 볼륨이 있는 케이스 | 진입 스크립트 → 모듈 → 검색 | 결과·북마크 또는 일치 볼륨 없음 |
| UC-02 | 분석자; 모듈 결과 존재 | 목록 필터 → 행 확인 → CSV/SQLite 내보내기 | 출력 파일 또는 오류 |
| UC-03 | 분석자; Prefetch/LNK/휴지통 증거 | 지원되는 추출 작업·대상 경로 선택 | 로컬 추출 파일; 모듈별 지원 차이 |
| UC-04 | 분석자; 선택 증거·쓰기 가능한 경로 | Timeline → Build DB → 완료 대기 | 통합 DB; 오류 시 출력 검사 |
| UC-05 | 분석자; 외부 시각화 복원·경로 확인 | 브라우저 → DB 선택 → 시간 범위 선택 | 과거 의도된 흐름; 현 저장소는 자산 누락으로 제한 |

## 인수 기준의 한계

각 기능은 [검증 계획](TEST_PLAN.ko.md)의 런타임 케이스로 확인해야 합니다. DB 생성만으로 시각 정확도, 전체 수집 범위, 행위 해석 신뢰성을 입증하지 않습니다. 성능·가용성·버전 지원 목표는 남아 있지 않으므로 향후 릴리스 전에 측정 방법과 기준을 정해야 합니다.
