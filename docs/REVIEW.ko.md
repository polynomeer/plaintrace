## 범위와 보존

2026-10-13 보존 기준 `archive/pre-improvements-2026-10-13` (`758bfc5`)과 대조했습니다. 변경한 EnScript 파일 6개, 아카이브/문서 도구와 영문·국문 산출물을 검토했습니다. 기준 태그, 원본 매니페스트와 재구성된 과거 커밋 263개는 그대로 유지하며 master 통합은 히스토리를 재작성하지 않고 현대 커밋을 추가합니다. 소스 수정은 파일별 BOM, 인코딩과 CRLF를 보존합니다. 수동 소스 검토와 휴대 가능한 계약 검증이며 독립된 외부 리뷰 또는 EnCase 런타임 인증은 아닙니다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| 휴대 가능한 회귀 검사 | 11개 통과: 기존 7개와 재실행 목록 초기화, 쿼리/검색어 인용, Recent 실패 배치 롤백, 타임라인/디코더 경계 검사 |
| 자동 생성 소스/스키마 참조 | 통과; 현재 소스에서 문서 4개 재생성 |
| 영문·국문 문서와 링크 | 기술 리터럴과 언어별 링크를 포함한 저장소 검사 통과 |
| 과거 아카이브 전용 검증 | 보존 소스 13개, 당시 README, 커밋 기록 263개와 원본 트리 검증 통과 |
| 소스 인코딩과 구조 | 변경 소스의 BOM, CRLF와 중괄호 균형 검사 통과 |
| 공백 | git diff --check 통과 |
| Windows/EnCase 컴파일 및 실행 | 수행하지 않음; 호스트/SDK/증거 픽스처 없음 |

휴대 가능한 검사는 소스에서 추출한 SQL을 Python SQLite에서 실행하고 제한된 문자열 표현식을 평가합니다. URL 픽스처는 소스에서 추출한 매개변수명으로 만든 모델을 사용하며 디코더 경계는 정적으로 검사합니다. EnScript 제어 흐름이나 UTF-8 호스트 디코더를 실행한 결과가 아닙니다. 롤백 검사는 SQLite 트랜잭션 의미와 소스의 롤백 분기를 확인하며 호스트 파일 잠금과 API 실패 정리는 재현 검증이 필요합니다.

## 남은 한계와 호스트 승인 조건

이 브랜치를 실행 준비가 된 버전으로 판단하려면 기록된 Windows/EnCase 환경에서 진입점과 모든 include를 컴파일해야 합니다. [테스트 계획](TEST_PLAN.ko.md)의 T-02, T-08부터 T-13, T-17과 T-18을 우선 실행합니다. 새 리더 수명, 빈/반복 선택, 쿼리 및 잘못된 UTF-8 픽스처, 레지스트리 FILETIME/시간대 해석, 출력 잠금/롤백, 부분 출력과 차트를 검증해야 합니다.

기존 출력 가드는 파일을 읽기 위해 열 수 있는지만 확인하므로 원자적인 생성이나 읽을 수 없는 기존 파일 및 경합 보호를 보장하지 않습니다. 초기화 실패로 부분 출력이 남을 수 있고 개별 아티팩트 헬퍼는 모든 오류를 상위로 전달하지 않습니다. 따라서 최종 완료 메시지도 수집 완전성을 보장하지 않습니다. Recent append 내보내기는 재실행 시 중복 행이 생길 수 있습니다. 검색어 작성 외 브라우저 방문/다운로드 SQL은 여전히 인용 처리가 없습니다. 고정 오프셋 파서, ControlSet001 가정, 시간대 의미, 누락된 HTML/JS, 고정 경로, 출처 필드와 휴지통 내용 복구는 미해결 상태입니다. 잘못된 바이트 또는 퍼센트 인코딩 NUL의 UTF-8 대체/잘림 동작은 호스트 검증이 필요하며 원시 증거 URL은 유지됩니다.

최종 통합은 일반 병합 커밋으로 승인되었습니다. 병합 후에도 EnCase 컴파일과 실행은 미검증 상태입니다. 강제 푸시, 과거 날짜 재지정이나 아카이브 교체는 포함하지 않습니다. 브랜치 전체 동작은 [개선 기록](IMPROVEMENTS.ko.md)을 확인하세요.
