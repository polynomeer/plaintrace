# Local report workbench

**English** | [한국어](WORKBENCH.ko.md)

2026-10-27 · Local report-workbench implementation. Report schema 15 and parser semantics retained.

## Run and workflow

The proposed three-pane screen is now a runnable, read-only report viewer: navigation, source inventory, provenance inspector and paginated observations. Run from the checkout, or install the wheel and use the console entry point. The server prints its chosen loopback URL; the browser opens only when explicitly requested. No Node.js, frontend build step, CDN or third-party Python runtime package is required to use the UI.

```sh
python -m plaintrace.ui --open
plaintrace-ui --open
python -m plaintrace.ui --port 8767
python -m plaintrace --input /path/to/History --output report.json
```

Open the JSON report with the report picker. Reports replace the current workspace only after validation. The default screen is empty; the optional demo is clearly synthetic and can be cleared. Demo preview is available by appending the demo query parameter to the printed URL. Analysis itself stays in the existing CLI; this UI does not parse raw DB/hive/EVTX files or accept SQLite report imports.

## Implemented interactions

Source search and format filters operate on report fields, never guessed evidence OS. Selecting a source shows path/hash metadata, raw source information, observations and source-scoped diagnostics. The viewer supports all thirty schema-15 collections, preserving duplicate records and original record references. Record dialogs render data as text and support explicit clipboard copy. Download saves the original selected File/Blob rather than reserializing parsed numbers.

Timeline rows use explicit UTC fields from visits, keywords, downloads, events and Recycle Bin. Download start/end are separate references; URL summaries and proxy search times remain labeled. Registry key times are not promoted to activity events. Ordering retains up to seven fractional digits by normalized string comparison, not millisecond Date sorting. This is a display projection, not a new report collection, identity join, execution/success inference or causality claim.

Light, dark and system appearance follow the same product tokens. Native buttons/selects, skip navigation, visible focus, native modal dialogs and reduced-motion rules are included. Source/observation/timeline pages render 30/20/30 items; large reports never produce a DOM row for every record. Support information is a checked projection of the M0 registry and distinguishes limited parsers, planned macOS/Linux families and historical Python-host CI results.

## Bounds and preservation

Only UTF-8 Plaintrace JSON with format version 15 is admitted. The viewer checks declared counts, mandatory collections, source identity uniqueness and record references. Bounds apply together: 16 MiB input, 100,000 total collection records including sources/diagnostics, 1,000 sources, 64 nesting levels, 300,000 decoded JSON nodes and 1,048,576 UTF-16 code units per decoded string. A complex report can hit a structural limit before the record ceiling. Nonfinite and numerically unsafe magnitudes are rejected; exact raw FILETIME/counter strings remain strings.

Raw-record display/copy is limited to 2 MiB; oversized records direct the examiner to original-report download. Diagnostics show at most fifty entries per selected source with the total explicitly visible. Paths, URLs, command strings and XML are inert text: no target navigation, path expansion or execution. Report data is not stored in localStorage, IndexedDB, cookies or server files. Clearing/reloading drops workspace references; this is not a forensic secure-erasure guarantee. User-created downloads and clipboard copies remain the user's responsibility.

## Local server and packaging

The Python standard-library launcher binds only IPv4 loopback. Its fixed in-memory asset allowlist exposes packaged HTML/CSS/ES modules/SVGs, not the current directory, arbitrary evidence files or parser APIs. Only static GET/HEAD are implemented; mutation/upload routes are absent. Host/Origin checks, no-store, no-referrer, nosniff, frame denial and a CSP with no network connections constrain the surface. The local asset server is not an authenticated multi-user service and must not be exposed by port forwarding or reverse proxies.

Assets ship as setuptools package data, so checkout and installed console use the same resources. Native HTML/CSS/ES modules avoid a separate production JavaScript toolchain. Selected Lucide 0.468.0 SVGs are bundled with their license and make no CDN requests. The support projection is regenerated by the shared tool when the canonical registry changes.

```sh
python tools/build_workbench_support.py
python tools/build_workbench_support.py --check
node --test tests/test_ui_model.mjs
python -m unittest discover -s tests -v
```
