# 설치·실행·사용 가이드

[English](USER_GUIDE.md) | **한국어**

2026-10-13 보존된 소스를 기준으로 작성한 사후 문서입니다. 2017년 당시의 원본 산출물이 아닙니다.

## 사전 조건

해당 EnScript API를 실행할 수 있는 Windows EnCase 환경이 필요하며 정확한 버전은 미확인입니다. 도움말은 Windows 7을 대상으로 표기하지만 모든 Windows 7 이미지나 이후 시스템 지원을 입증하지 않습니다. 런타임 검증 전에 테스트 케이스와 쓰기 가능한 로컬 출력 경로를 준비하세요. 설치 패키지·의존성 다운로드·샘플 증거·실행 가능한 HTML 타임라인은 제공되지 않습니다.

## 설정과 진입

1. 13개 `.EnScript`를 함께 두고 EnCase의 include 해석을 확인합니다. BOM·줄바꿈을 보존합니다.
2. Windows 증거가 있는 케이스를 열고 디바이스·볼륨·현재 뷰·선택 범위를 기록합니다. 진입은 CURRENTVIEW, 작업은 주로 CURRENTVIEW_SELECTED를 사용합니다.
3. `tools/inspect_sources.py`로 모듈의 고정 경로를 확인합니다. C 드라이브 출력과 케이스 내보내기 폴더를 확인하고 기존 DB를 보존합니다.
4. 호스트의 EnScript 실행 기능으로 `Plain View of Multi Artifacts.EnScript`를 실행합니다. 버전별 정확한 메뉴 이름은 확인되지 않았습니다.
5. 메인 화면이 없으면 콘솔을 확인하고 Windows 볼륨이 뷰에 있는지 점검합니다. 진입은 첫 일치 볼륨에서 종료합니다.

## 모듈 사용

관련 탭에서 지원되는 Search를 실행합니다. 작업 완료 후 행 수·대표 값을 확인하고 원본 증거와 대조합니다. 키워드 필터의 대상과 동작은 모듈별입니다. 지원되는 경우 키워드를 지워 행을 복원합니다. 문맥 메뉴에 CSV·SQLite 및 일부 파일 추출이 있습니다. 시스템 정보는 다른 아티팩트 탭과 같은 작업 흐름이 아니라 보고서·차트를 사용합니다.

빈 표만으로 활동이 없다고 판단하지 마세요. 선택 범위, 원본 아티팩트 부재, 포맷 가정, 오류가 빈 결과를 만들 수 있습니다. 콘솔과 예상 원본 경로를 함께 확인하세요.

## 타임라인

Timeline에는 Build DB·브라우저 버튼·Help가 있습니다. Build DB는 현재 표시 탭의 단순 병합이 아니라 독립된 두 번의 수집입니다. 고정 경로 통합 SQLite를 만들며 해석 전에 스키마·행 수를 확인해야 합니다. 도움말은 브라우저 실행→SQLite 선택→시간 범위 선택을 설명합니다. 누락된 HTML/JS 복원과 브라우저·HTML 고정 경로 확인 없이는 현 저장소만으로 마지막 단계를 수행할 수 없습니다.

## 문제 해결

| --- | --- |
| include·호스트 API 오류 | 소스 13개 존재, 호스트 버전, 인코딩 보존 |
| 메인 화면 없음 | 열린 케이스, 현재 뷰의 Windows 볼륨, 콘솔 |
| 빈 결과·부분 결과 | 선택 디바이스·항목 범위, 원본 경로, 포맷 버전 |
| 출력 파일 열기 실패 | 대상 존재·쓰기 가능 여부, 잠금, 경로 철자 |
| SQL 오류·반복 실행 충돌 | 기존 스키마, SQL 문법, 데이터의 작은따옴표 |
| 필터 후 값 변경 | 행 복사·생성자 인자 순서, 필터 전 결과 대조 |
| 브라우저 실행 실패 | 실행 파일 경로, HTML 경로, 자산 누락 |
| Still Processing·닫기 제한 | 스레드·세마포어 상태, 로그 보존·완료 확인; 검증된 취소 계약 없음 |

## 새 clone의 아카이브 검증

`python3 tools/inspect_sources.py`는 Python 3만 있으면 됩니다. `tools/verify_archive.py`는 로컬 `refs/archive/pre-reconstruction`과 전체 재구성 커밋도 요구합니다. 일반 원격 clone에는 이 로컬 백업 ref와 ignore된 bundle이 자동 포함되지 않습니다. 원본 tree까지 검증하려면 최초 재구성 작업 공간 또는 별도 보존 백업이 필요합니다. 기준 스냅샷 부재를 런타임 실패로 보고하지 않습니다.

## 실행 기록

실행일·소스 커밋·EnCase/Windows 버전·증거 ID·현재/선택 범위·원본 시간대·출력 경로/해시·테이블 행 수·표본 대조·콘솔 오류를 기록합니다. 증거·출력은 Git에 넣지 않습니다. [검증 계획](TEST_PLAN.ko.md)과 [유지보수](MAINTENANCE.ko.md)를 참조하세요.

## 확인된 구현 한계

USB 레지스트리 결과는 CSV 내보내기를 제공하고 USB 이벤트 결과는 CSV와 SQLite를 제공합니다. 이벤트 CSV 헤더에는 레지스트리 필드명이 사용되므로 가져오기 전에 소스와 열 순서를 대조해야 합니다. Link 뷰는 CSV, SQLite 및 추출 동작을 구현하지만 별도 Recent 뷰는 SQLite 메뉴 항목에 대응하는 처리 분기가 없습니다. Recent Documents는 뷰어별 CSV 파일과 App_Documents 테이블을 생성하며, 뷰어별 SQL 정의는 주석 처리되어 있습니다.

시스템 차트는 선택된 케이스 항목을 직접 읽고 Prefetch와 웹 차트는 SQLite를 조회합니다. 종료 시각 헬퍼에는 반환할 타임스탬프를 실제로 대입하는 코드가 없습니다. 브라우저 검색어 처리는 CSV 생성에서 이미 소비한 리더를 다시 사용합니다. 전체 타임라인 수집은 Web_Visit과 Web_Host를 생성하지 않고 브라우저 행 삽입을 시도하며, IE 삽입문 하나에는 VALUES가 없습니다. 이는 호스트에서 재현해야 할 소스 수준의 발견 사항이며 빈 결과를 증거 부재로 해석해서는 안 됩니다.

추출 동작은 선택한 행의 키와 내보낸 바이트를 독립적으로 검증해야 합니다. 휴지통 $I 메타데이터 파싱만으로 대응하는 $R 내용의 복구가 입증되지는 않습니다.
